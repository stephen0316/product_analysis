# 产品后评估本地工具

本机离线 Web 工具。覆盖 13 条重点产品线、六个大维度与 10 个评分列。规则通过“模型中心”按版本管理；当前数据适配器已支持市场份额、五项经济效益、产品三效、自研能力和品质服务，缺失项显示“待完成”，不以零分替代。

## 公司服务器与自动部署

当前公司内网无法访问 GitHub，且已有内部 GitLab / Jenkins / Harbor 等平台，应优先接入 [内网自动部署方案](docs/deployment-intranet.md)。下面的 GitHub Actions 配置保留为可访问 GitHub 环境下的方案，不适用于当前内网。

公司服务器可使用 Docker Compose。仓库提供 GitHub Actions：推送 `main` 后自动测试、构建并检查镜像，随后通过公司自托管 Runner 发布。技术人员首次接入服务器并设置 `AUTO_DEPLOY=true` 后启用自动部署；接入前只运行检查和镜像打包。部署任务默认限定私有仓库、Linux x64。

服务器准备、密钥配置、模型及历史数据迁移、启用步骤、备份和失败处理见 [部署交付手册](docs/deployment.md)。当前提供的是配置，实际服务器部署仍需接入验收。

## 启动

首次运行：

```bash
python3 -m pip install -r requirements.txt
cd frontend && npm install && npm run build && cd ..
python3 run_local.py
```

浏览器打开 `http://127.0.0.1:8765`。之后只需执行 `python3 run_local.py`。服务仅监听 `127.0.0.1`；上传文件、SQLite 评估记录保存在项目的 `local_data/`，不会传往云端。若需改存储位置，设置 `PRODUCT_EVAL_DATA_DIR`。

开发前端并实时预览时，另开一个终端运行：

```bash
cd frontend
npm run dev
```

然后访问 `http://127.0.0.1:5173`。Vite 会把 `/api` 代理到 `8765`，保存前端源码后自动热更新。

公司服务器副本的运行配置已保留为 `docker-compose.company.yml`，使用方式见 [公司服务器配置](docs/deployment-company.md)。根目录通用 Compose 继续配套原有发布脚本，两种方式单独使用。

## AI 模型：本地 Gemini，云端沿用 GLM

规则识别、文件映射、调优目标解析和报告评价共用模型客户端。评分与排名由本地引擎执行，模型输出需通过本地业务校验。

本地 `python3 run_local.py` 未指定 `LLM_PROVIDER` 时默认使用 Gemini。显式设置如下，避免加载云端环境后选错服务：

```bash
export LLM_PROVIDER=gemini
read -s GEMINI_API_KEY
export GEMINI_API_KEY
python3 run_local.py
```

`GEMINI_MODEL` 默认 `gemini-2.5-flash`；报告可用 `GEMINI_REPORT_MODEL` 单独配置。本地不会加载服务器 `.env`。

云端保留服务器现有 GLM 网关、密钥、`LLM_MODEL` 和可选 `LLM_REPORT_MODEL`。`LLM_PROVIDER=openai` 表示使用 OpenAI 兼容协议，并不表示调用 OpenAI 的模型。两份 Compose 默认走此协议，并要求明确填写 `LLM_MODEL`，避免缺失配置时使用其他默认模型。GLM 完整型号以服务器原配置为准，本仓库不猜测替换。

不要覆盖服务器原有 `.env`；`.env.example` 只供新部署参考，模型名称需由技术人员填写为已有 GLM 标识。所有密钥只保存在对应环境，不提交 Git、不打入镜像。

显式 provider 选择 `gemini` 或 `openai`，不会跨服务借用密钥；未指定 provider 的旧调用保持按密钥选择的兼容行为。

规则识别使用 `semantic-plan-v1`，提取数据需求、年度、排序、平均方式、增幅分母和赋分参数，后端校验并计算，不执行 AI 生成的公式或代码。规则识别只发送指标名称、规则摘要、来源提示及能力目录；主动生成 AI 评价时会发送真实指标、排名和经营说明摘要，不发送原始上传文件。评价与建议需人工审阅。

年度范围由原始输入依赖推导，同比同时需要本年和上年数据；AI不再独立生成可能与输入冲突的年度范围。“当年／上年”随批次年度变化，“25年／2025年”保留为明确年份约束；规则限定年份与批次不一致时阻止计算并提示，不能静默替换为另一年。年度语义新增案例已完成离线验收，真实联网联调状态见 [年度规则验收说明](docs/semantic-year-live-check.md)。

## 评估 SOP

1. 选择评估年度并创建批次、绑定已发布模型。评估年度指被评估的数据年度，默认上一自然年度（例如 2027 年开展评估时默认选择 2026 年），同时核对 13 条重点产品线及规则版本。
2. 批量上传 Excel。系统依据模型规则生成原始数据清单，并自动匹配文件、工作表和字段；只有缺失或有歧义时才需要确认。市场表的“安全芯片”映射为“芯片”。
3. 计算并处理缺失、非数值、重复、零基数和不同来源冲突。
4. 在指标评分总览点击分数，核对原值、步骤、排名、公式、来源文件和单元格。
5. 在分数明细中复核各产品的计算链与缺失项。
6. 原因分析、处置建议和审阅意见均为选填；点击“生成报告”保存内容并生成 DOCX，成功后显示报告导出入口。评分总表可独立导出；修改审阅内容或评分结果后需重新生成报告。

“模型中心”位于导航底部的系统配置区，不计入以上 SOP。仅在需要调整规则或发布新版本时进入。

## 已确认评分规则

- 并列采用竞争排名：同分同名次，后续跳位。得分 `10 - 0.5 × (名次 - 1)`。
- 市场份额：取最新年度原值，在 13 条重点产品内降序排名赋分。
- 五项经济效益：收入、毛利、毛利率、营业利润、营业利润率按五个最小指标独立配置，各占 10 分；每项分别取当年值和增幅 `(当年 - 上年) / ABS(上年)`，增幅保留正负号，各自排名赋分；两项得分取平均，再排名赋分。零基数标记为不可计算。
- 产品三效：劳产、元效、人效各自排名赋分；三项得分取平均，再排名赋分。
- 自研能力：自研收入占比与研发投入产出比（收入／成本）分别排名赋分，平均后再次排名；占比超过 100% 按 100% 计，不取“结算”项，物联卡例外采用“物联卡网结算”。
- 能力评测：当前可使用占位原始分，排名赋分。
- 品质服务：识别“产品线”和“产品推广满意度”原始表头，按原值排名赋分。支持前 12 行内的标题/表头及空格、换行；多年度列按评估年度匹配，无年度标记的单列按批次年度使用。年度不符或多列、多工作表存在歧义时要求确认，不自动取第一列，也不把排名、得分列当作原始数据。已上传但未识别的文件可通过“调整用途”选择品质服务重新匹配，无需重复上传。

## 模型治理

计算方案、离线规则、发布检查和动态结果状态的实现及验收记录见 [模型可执行边界](docs/executable-model-contract.md)。

- 生命周期：草稿 → 发布；可同时保留多个已发布模型供新批次选择。发布版本不可直接修改，只能复制为新草稿。
- 两级结构：指标按顺序平铺配置，每项指标选择一个归属维度；维度通过下拉框中的“修改维度”入口新增、重命名或删除。
- 参与规则：模型中存在的指标全部参与计算；不设置启用勾选，不需要的指标直接从草稿中删除。
- 发布校验：每项指标必须选择归属维度，指标权重合计必须为 100。
- 规则摘要：用于记录业务计算口径；AI 将摘要转换为结构化计算方案；程序验证原始数据需求、计算策略和参数，展示实际执行含义。上传环节沿用指标内部数据契约进行本批次来源匹配；本地引擎执行已支持的计算策略，不直接执行自然语言或 AI 公式。
- 数据来源：模型中心负责定义“需要什么、如何计算”，上传环节只绑定“本批次数据来自哪里”。同一指标可以由多份文件共同提供原始输入，派生值不要求用户关联某一列。
- 历史可追溯：评估批次绑定具体模型版本，后续发布新模型不会改写历史结果。
- 上线前预演：可用历史批次模拟候选模型，并对比得分、排名、名次变化和缺失指标。
- 审计记录：系统自动概括创建、复制、保存和发布事件，并记录到秒的时间。
- 删除约束：未被批次引用的草稿和已发布模型均可删除，但系统至少保留一个已发布模型；被评估批次引用的模型受保护。评估批次删除前二次确认，删除后同步清理其结果、审阅记录与上传文件。

## 导出内容

- 报告补充按当前模型生成的维度分析、13条重点产品详细评价、提升建议及真实指标雷达图。可先生成 AI 草稿，逐产品审阅修改后再生成报告；AI 不能改变评分、推断缺失数据或自动决定红黄牌及人员调整。详细结构和依据边界见 [报告结构说明](docs/report-structure.md)。

- `重点产品-雷达图维度`：列出当前批次绑定模型中的维度、指标、权重、规则和各维度的导出排序指标。
- 每个模型维度生成一个独立 Sheet；同一维度下的多个指标合并展示，并按该维度配置的排序指标排列产品。
- 明细表头由“数据年度 + 当前指标名称”动态生成。指标改名后导出表头同步改名；市场/行业份额只展示参与排名的数据年度，不再附带更早年度的展示列。
- `重点产品-总分`：按当前模型中的指标动态生成评分列，并输出可用的总分与排名；缺失项保留待完成状态，不以零分补齐。
- DOCX：沿用样稿的“上年度改善、本年度结果、下一步工作”结构，自动填入已核实的数字和图表；缺失资料和人工结论明确待审阅。

样稿中的旧分数、产品矩阵、分析结论不会被复用。请在正式使用前复核字段映射和客户口径。
