# 产品后评估本地工具

本机离线 Web 工具。覆盖 13 条重点产品线、六个大维度与 10 个评分列。规则通过“模型中心”按版本管理；当前数据适配器已支持前 7 项，缺失项显示“待完成”，不以零分替代。

## 启动

首次运行：

```bash
python3 -m pip install -r requirements.txt
cd frontend && npm install && npm run build && cd ..
python3 run_local.py
```

浏览器打开 `http://127.0.0.1:8765`。之后只需执行 `python3 run_local.py`。服务仅监听 `127.0.0.1`；上传文件、SQLite 评估记录保存在项目的 `local_data/`，不会传往云端。若需改存储位置，设置 `PRODUCT_EVAL_DATA_DIR`。

## 评估 SOP

1. 创建年度批次并绑定已发布模型，核对 13 条重点产品线及规则版本。
2. 分别上传市场份额、经济效益、产品三效 Excel；确认工作表、年度、字段列、单位和产品线映射。市场表的“安全芯片”映射为“芯片”。
3. 计算并处理缺失、非数值、重复、零基数和不同来源冲突。
4. 在十维总览点击分数，核对原值、步骤、排名、公式、来源文件和单元格。
5. 在分数明细中复核各产品的计算链与缺失项。
6. 由负责人填写原因分析、处置建议和审阅意见，导出评分总表与 DOCX 报告。

“模型中心”位于导航底部的系统配置区，不计入以上 SOP。仅在需要调整规则或发布新版本时进入。

## 已确认评分规则

- 并列采用竞争排名：同分同名次，后续跳位。得分 `10 - 0.5 × (名次 - 1)`。
- 市场份额：取最新年度原值，在 13 条重点产品内降序排名赋分。
- 五项经济效益：收入、毛利、毛利率、营业利润、营业利润率按五个最小指标独立配置，各占 10 分；每项分别取当年值和绝对增幅 `ABS((当年 - 上年) / 上年)`，各自排名赋分；两项得分取平均，再排名赋分。零基数标记为不可计算。
- 产品三效：劳产、元效、人效各自排名赋分；三项得分取平均，再排名赋分。
- 自研能力：自研收入占比与研发投入产出比（收入／成本）分别排名赋分，平均后再次排名；占比超过 100% 按 100% 计，不取“结算”项，物联卡例外采用“物联卡网结算”。
- 能力评测：当前可使用占位原始分，排名赋分。
- 品质服务：按原表原始值排名赋分。

## 模型治理

- 生命周期：草稿 → 发布 → 归档；发布版本不可直接修改，只能复制为新草稿。
- 维度即评分项：业务用户只维护维度名称、权重和规则摘要；内部计算标识不在界面中暴露。
- 参与规则：模型中存在的维度全部参与计算；不设置启用勾选，不需要的维度直接从草稿中删除。
- 发布校验：维度权重合计必须为 100。
- 规则摘要：用于记录业务计算口径；未来接入 AI 解析后，先转换成结构化规则并由用户确认，再驱动计算。
- 历史可追溯：评估批次绑定具体模型版本，后续发布新模型不会改写历史结果。
- 上线前预演：可用历史批次模拟候选模型，并对比得分、排名、名次变化和缺失指标。
- 审计记录：创建、复制、保存、发布和归档均保留变更原因与时间。
- 删除约束：草稿和未被批次引用的归档模型可删除；已发布模型及被批次引用的模型受保护。评估批次删除前二次确认，删除后同步清理其结果、审阅记录与上传文件。

## 导出内容

- `重点产品-总分`：C～L 为十个评分维度，M 为总分，N 为排名；当前 M、N 留空。
- `计算明细`：原值、中间值、各级名次、得分、单位、公式、来源单元格。
- `校验与待确认`、`数据来源`：异常、待确认规则、上传文件哈希与映射。
- DOCX：沿用样稿的“上年度改善、本年度结果、下一步工作”结构，自动填入已核实的数字和图表；缺失资料和人工结论明确待审阅。

样稿中的旧分数、产品矩阵、分析结论不会被复用。请在正式使用前复核字段映射和客户口径。

## 验证

```bash
python3 -m unittest discover -s tests -v
cd frontend && npm run build
```

端到端测试在本机原表可用时会上传三类表，核对 13 × 7 条评分链、70 分覆盖、空白正式总分，以及 XLSX/DOCX 可打开。
