# 团队共享账号访问

团队共用一个账号，登录后可查看、编辑、导出全部模型与批次。不开放注册，不提供创建、停用或管理其他账号的功能。网页右上角仅提供“修改密码”和“退出”。

## 首次初始化

服务器首次部署时，由你或运维在服务器终端初始化一次共享账号，密码按交互提示输入，不写入代码或命令行参数：

```bash
docker compose -f docker-compose.company.yml exec product-fenxi python -m post_evaluation.auth admin
```

通用 Compose 使用服务名 `app`。本机开发使用 `python3 -m post_evaluation.auth admin`，然后执行 `python3 run_local.py`。首次登录需修改初始密码。

账号保存在 SQLite 中。仅部署代码不会携带本地账号；完整迁移数据库才会携带账号。服务器保留原有数据卷时，更新代码、容器重启不会丢失账号、模型或批次。不要用本地数据库覆盖服务器已有业务数据，也不要执行 `down -v`。

## 日常使用

- 将同一个账号和密码提供给获授权的团队成员，多人可同时登录，无需操作终端或创建个人账号。
- 网页“修改密码”需要原密码、新密码和确认新密码，密码须为 12–128 个字符；支持小眼睛显示/隐藏。
- 修改共享密码后所有设备的旧会话立即失效，团队成员需要使用新密码登录。退出只结束当前会话。
- 如果忘记密码，由服务器操作者交互重置原共享账号，无需重新建账号：

```bash
docker compose -f docker-compose.company.yml exec product-fenxi python -m post_evaluation.auth admin --reset-password
```

重置后会撤销全部旧会话，下一次登录必须修改初始密码。必须使用实际共享账号名称替换示例中的 `admin`。

## 部署与验证

- 上线前备份原数据库和上传目录，保留 Compose 项目名及数据卷。
- 生产通过 HTTPS 网关访问，保留原始 Host；应用默认使用 Secure Cookie。公司 Compose 的应用端口仅绑定 `127.0.0.1:4100`。网关位于其他主机时由运维另行限制来源。仓库修改不代表公司服务器已更新。
- 本机 `run_local.py` 仅监听 `127.0.0.1`，默认允许本机 HTTP Cookie。如环境显式设置 Secure Cookie，则仅在本机调试终端使用 `PRODUCT_EVAL_COOKIE_SECURE=false`。
- 验证匿名请求不能访问模型、批次、结果、报告或导出；团队账号多设备可正常使用；改密后所有旧会话失效；历史文件与计算结果仍存在。
- 旧版本已初始化的首个账号继续使用，无需重新创建。如旧库包含多个账号，仅最早创建的账号有效，其他账号记录保留但不再允许登录；不自动删除历史记录。

## 安全边界

密码使用带随机盐的 scrypt 摘要；会话令牌在服务器仅保存摘要，浏览器使用 HttpOnly、SameSite=Strict Cookie。所有业务 API 和文档入口统一鉴权；写请求校验 CSRF token。只有登录和不含业务数据的健康检查公开。

会话最长 8 小时，30 分钟无请求后过期，自动轮询也计为活动。登录尝试按账号和连接来源限流。共享账号日志不能区分具体操作人，获知密码就具有完整权限。

`auth_events` 记录登录、改密及认证写请求的时间、账号、路径和状态，不记录密码和文件正文。回滚到未鉴权旧版前应先由网关关闭访问。测试中的身份替身仅用于原有业务回归，真实认证由独立测试覆盖，生产不提供绕过鉴权的开关。
