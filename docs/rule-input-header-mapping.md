# 规则数据名称与上传表头联动

规则中的原始数据名称与上传映射共用模型输入契约。内部计算字段和业务数据名称分开保存：例如“品质服务”指标摘要为“按服务评分降序排名赋分”，仍使用已有单项排名算法，匹配名称为“服务评分”，上传表头无需改成“产品推广满意度”。

明确的简单单项排名语句可以本地识别；复杂规则通过结构化方案的 inputs.name 保留摘要中的业务字段名称和各自期间。规则解析、上传关联、计算依据的字段显示使用这些名称。自动匹配只使用当前摘要中的明确名称，忽略过期或摘要没有声明的解析名称；不会把指标标题当成原始数据名称。

上传优先匹配相同的数据名称，统一处理中英文括号、空格、换行和年份。明确的年份、上年/当年角色及工作表年份参与校验；重复同名列、多个匹配工作表、年度冲突均保留为未确认映射。传统财务多行表头、自研和三效格式继续沿用原识别路径。选择或调整文件用途后也使用相同的模型匹配逻辑。

新增上传和调整用途时使用新逻辑。原来已保存的字段列映射不会被静默改为另一列；既有文件如需重新匹配，可通过“调整用途”重新确认。

验证：8 项新增用例覆盖同名匹配、指标标题与数据名区别、重复列/工作表、年度冲突、手动指定用途、复合规则跨期数据名、过期解析及未声明名称；接口端到端完成“规则识别 → 发布模型 → 创建批次 → 上传服务评分表 → 自动关联 → 校验 → 计算”，并核对来源单元格。全量 132 项测试通过。
